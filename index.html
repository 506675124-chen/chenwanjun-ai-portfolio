自我介绍

我是陈婉君，常驻深圳。过去几年我在留学咨询一线，完整负责本升硕全周期服务——从选校策略、背景规划、文书打磨到录取后流程。这段经历让我养成了一种习惯：先把问题框清楚，再动手做东西。

近一年，我把这套习惯用到了 AI 上。我主导搭建了一个自然语言驱动的个人工作台，把顾问经验沉淀成可复用的规则与用例；也独立完成了一个含 11,284 条结构化学位数据的全球院校库，并把它部署进生产环境。我没有计算机科班背景，但我相信——非硬核，也能把 AI 真正用起来。

我正在寻找 AI 知识库 / RAG 产品设计、AI 产品运营、Agent 产品运营或 AI Business Analyst 方向的机会，希望把「业务翻译 + 产品落地」的能力，带到更体系的 AI 团队里。

1

AI 驱动个人工作台（Agent / 工作流）

自然语言指令Agent工作流自动化中台

背景：留学顾问大量重复劳动（建档、选校、规划、文书），依赖个人经验，难复制。

我的角色：产品构想 + 规则设计 + 用例编写，与开发协作落地。

做了什么：用自然语言指令驱动 AI 完成页面生成、数据整理、流程自动化；搭建含 29 人 学生中台 + 规划引擎 + 文书工坊的双端工作台，沉淀 6 个核心用例。

产出数据：学生建档 30 分钟 → 2 分钟；选校 / 规划 / 文书 / 节点提醒 / 行前指导全流程标准化。

证明能力：Agent 场景定义、工作流编排、用例设计——即 Agent 产品运营 / 设计师的核心日常。

2

全球硕士院校库（知识工程 / RAG 底座）

知识工程RAG数据清洗生产部署

背景：选校依赖零散信息，质量与一致性无法保证。

我的角色：数据标准制定 + Python 清洗 + 验收设计。

做了什么：构建含 11,284 条 全球硕士项目的结构化学位库；用 pipeline 自动补全 1,347 条 项目的 features / duration / curriculum，并部署到 生产环境 v9。

产出数据：自设验收标准、多次质量抽查，确保数据可解释、可复核。

证明能力：知识库 schema 设计、信源质量把控、上线验收——即 RAG 知识库产品设计师的关键能力。

📷 截图位：院校库检索 / 数据看板截图
3

营养学信息源导航（跨域可迁移证明）

信源分级知识导航跨域迁移

背景：营养学学生面对海量、良莠不齐的信息，难辨可信度。

我的角色：信息架构设计 + 信源评审。

做了什么：为营养学学生搭建跨国信源导航，将信息源分为 官方 / 行业 / 商业 三级，并明确「引用前回到一手来源核实」。

证明能力：信源治理与知识库内容质量把控——可直接迁移到企业 RAG 知识库的「喂什么料」决策。

📷 截图位：营养学信息源导航文档 / 结构图（实物见 D:\1\营养学信息源导航.*）
4

四年规划生成器（规则引擎）

规则引擎规划自动化标准化

背景：学生规划因人而异，但顾问时间有限，难以规模化。

我的角色：把顾问经验抽象为规则模板。

做了什么：输入学生基础信息，规则引擎自动输出分阶段规划（语言 → 背景提升 → 申请节奏），含里程碑与截止日。

证明能力：把隐性经验显式化为可配置规则——对应 AI 产品中「提示词 / 规则 / 知识沉淀」的设计思维。
