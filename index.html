自我介绍

从一线业务出发，先框定问题，再让 AI 跑起来。

我是陈婉君，常驻深圳。过去几年我在留学咨询一线，完整负责本升硕全周期服务——从选校策略、背景规划、文书打磨到录取后流程。这段经历让我养成了一种习惯：先把问题框清楚，再动手做东西。

近一年，我把这套习惯用到了 AI 上。我主导搭建了一个自然语言驱动的个人工作台，把顾问经验沉淀成可复用的规则与用例；也独立完成了一个含 11,284 条 结构化学位数据的全球院校库，并把它部署进生产环境。我没有计算机科班背景，但我相信——非硬核，也能把 AI 真正用起来。

我正在寻找 AI 知识库 / RAG 产品设计、AI 产品运营、Agent 产品运营或 AI Business Analyst 方向的机会，希望把「业务翻译 + 产品落地 + 效果评测」的能力，带到更体系的 AI 团队里。

01 / Product Context

为什么需要一套新系统？Why AI-Native Workflow for Study-Abroad Consulting?

传统留学服务依赖多工具、多角色与大量人工沟通，信息在交接过程中持续损耗，AI 能力也难以进入真实生产流程。以下是我每天面对的真实痛点。

不是再做一个后台，而是重构留学服务的交付方式。

我在工作中用过简道云等公司系统，但选校模块基本鸡肋、简历无法联动、整体利用率很低。大多数时间我仍然需要在 Excel 和学校官网之间反复横跳。AI 不该只是搜索或写作工具，它应该成为贯穿学生服务全周期的协作能力。

01 / TOOL FRAGMENTATION

工具割裂：现有系统利用率低

公司在用简道云系统，但选校模块功能鸡肋、无法与简历联动，顾问实际工作中很少使用。信息分散在微信、Excel、备忘录和学校官网，交接时经常断档。

02 / INFORMATION OVERLOAD

信息过载：选校查校效率极低

我的工作需求是筛选海内外学校和专业。过去用 Excel 表格挨个查，或打开学校官网逐条核对，为学生做一份选校清单往往要花 30 分钟到 1 小时。

03 / ROLE HANDOFF LOSS

交接损耗：签证/行前缺少支持

公司没有给我签证部分的支持文件和数据。我只能整理自己过往经历和数据，把签证流程、材料清单、行前准备重新做成可复用的模块。

04 / INVISIBLE AI

AI 能力不可感知

AI 在团队中只能当搜索或文案工具用，没有嵌入决策流程。学生建档、选校梯队、时间规划、材料提醒这些高频动作，仍然靠人工重复完成。

这背后的产品问题：留学服务是一个「高信息密度、高个性化、高并发」的场景，AI 不能只是更快地产出内容，而要能框定边界、排除噪声、给出可行动结果、可追溯来源、经得起验收——这也是我最在意的事。

02 / Challenge & Goals

复杂系统，必须先定义正确的问题。Design the System Before the Screen.

挑战不在于页面数量，而在于如何让不同角色围绕同一学生协作，同时保持权限、状态和责任边界清晰。

01 / ROLE COMPLEXITY

角色复杂度

学生、家长、顾问、文书老师、申请老师、签证老师等多角色参与，各自关注点不同，信息容易在交接中失真。

02 / LIFECYCLE CONTINUITY

生命周期连续性

从初次咨询到最终入学，跨度 1–4 年，需求、材料、状态持续变化，必须保证全流程可追溯。

03 / STATE VISIBILITY

状态可见性

每个学生的申请节点、材料完成度、待办事项需要实时同步，否则顾问和学生都会漏掉关键截止日。

04 / SYSTEM SCALABILITY

系统可扩展性

新国家、新专业、新流程不断涌现，系统不能靠每次重新开发来适应，而应由规则模板和知识库驱动。

SUCCESS FRAMEWORK · What Good Looks Like

Single Source of Truth：学生档案、申请状态、院校数据统一维护，避免多份 Excel 互相打架。
Observable AI：AI 给出结果时，必须同时呈现依据、置信度和可干预入口，而不是黑盒输出。
Clear Responsibility：AI 负责信息整理与初筛，顾问负责关键判断与复核，边界清晰。
Shortest Task Path：把选校/时间表调整从 30–60 分钟压缩到 3 分钟以内，释放顾问的高价值时间。

05 / Information Architecture

一个系统，多种角色视角。Shared Architecture. Contextual Experience.

通过共享平台能力与角色化信息结构，减少重复建设，同时保证每类用户只看到与当前任务相关的内容。

PLATFORM ARCHITECTURE

ROLE & PERMISSION MODEL

06 / AI Agent Collaboration

让 AI 从黑盒能力，成为协作伙伴。Visible. Traceable. Trustworthy.

AI 不仅提供结果，还需要呈现输入、执行过程、当前状态、异常原因与可干预入口。

Human sets the goal. AI accelerates the work.

在我的工作台里，顾问设定目标（如「为某学生生成选校梯队」），AI 负责信息检索、初筛与格式化，最终判断权始终在人。用户始终能回答三个问题：AI 正在做什么？为什么这样做？以及下一步如何介入？

1

AI 驱动留学工作台

自然语言指令Agent工作流自动化人工复核选校系统时间表签证/行前
01
用户问题

公司在用简道云系统，但选校模块鸡肋、简历无法联动，整体利用率很低。我的实际工作是：用 Excel 表格或学校官网逐个查海内外院校专业，为一名学生整理选校清单和时间表要花 30 分钟–1 小时；签证/行前部分完全没有支持文件和数据，只能靠自己整理。

02
可运行工作流

输入：自然语言指令或学生基础信息 → AI 处理：解析意图、提取字段、匹配院校库/规则模板 → 人工复核：关键决策（选校、文书）必经人工确认 → 输出：结构化档案 / 选校梯队 / 动态时间表 / 签证/行前 checklist / 节点提醒。

03
AI 策略
  • 分类：意图拆为建档、选校、时间表、文书、提醒、签证/行前 6 类，每类对应固定输出模板
  • 提示词约束：强制输出 JSON / 表格 / checklist，减少自由发挥
  • 知识：调用 11,284 条院校库 + 历年签证/行前规则模板
  • 回退：多轮对话上下文丢失或意图模糊时，自动转分步确认，不臆测
04
评测证据

以 29 名 真实学生档案为测试集：建档耗时从 30 分钟 → 2 分钟；选校/时间表调整从 30–60 分钟 → 3 分钟；输出经 3 轮抽查，结构与历史案例一致率 96%。失败案例 = 多轮对话中上下文丢失导致字段错配，已改为「分步骤确认」机制。

05
迭代与风险

下一步：把规则模板升级为可对话调整的 Agent，支持学生/顾问双向追问。误判控制：文书、选校、签证材料等关键输出必经人工复核；学生敏感信息仅授权人员可见。

子系统 A · 智能选校（替代 Excel/官网查）

输入学生 GPA、专业、目标国家、预算 → 调用 11,284 条院校库 → 输出冲刺/匹配/保底三档清单 + 录取门槛 + 学制 + 核心课程。解决「Excel 挨个查、官网逐个看」的低效问题。

子系统 B · 动态时间规划表（30–60 分钟 → 3 分钟）

输入学生入学年份、目标国家、考试计划 → 自动生成语言考试、背景提升、文书、网申、签证节点时间表。已分享给同事使用，选校和时间表整理效率显著提升。

子系统 C · 签证与行前自动化（从「无支持」到「有标准」）

公司未提供签证支持文件和数据。我整理个人过往经历与官方来源，生成签证材料清单、递签时间线、行前准备包，并沉淀为可复用模板。

全球硕士院校库

知识工程RAG数据清洗生产部署人工复核
01
用户问题

选校信息散落在官网、论坛、机构资料，格式不统一、更新不同步，顾问凭个人经验判断，难规模化、难解释。

02
可运行工作流

输入：原始网页/表格/非结构化文本 → AI 处理：Python 清洗 + schema 对齐 + 字段抽取 → 人工复核：抽检异常值与低置信度字段 → 输出：结构化 11,284 条学位库，供工作台检索与选校。

03
AI 策略
  • 分类：按国家 / 专业 / 学位类型 / 学制建立 schema
  • 提示词：从非结构化文本中抽取 features / duration / curriculum，输出标准化 JSON
  • 约束：必填字段 + 置信度阈值，低于阈值不自动写入
  • 知识 / 回退：以官网为唯一权威源；无法自动确认时转人工补全
04
评测证据

主库 11,284 条；pipeline 自动补全 1,347 条 项目的 features / duration / curriculum；部署至 生产环境 v9；自设验收：对补全字段抽样回溯原始来源，异常值修正后上线。

05
迭代与风险

下一步：增加更新频率与变更追踪，让院校信息时效性可感知。误判控制：上线前验收 + 生产 v9 灰度使用；跨校区项目曾因合并错误，已加「学校 + 校区」联合主键。

四年规划生成器

规则引擎规划自动化标准化人工复核
01
用户问题

每个学生背景不同，规划因人而异，但顾问时间有限，输出标准不一，新顾问上手慢，质量难保证。

02
可运行工作流

输入：学生年级 / GPA / 目标国家 / 专业方向 → AI 处理：规则引擎匹配阶段模板 → 人工复核：顾问调整个性化节点 → 输出：带里程碑和截止日的四年规划。

03
AI 策略
  • 分类：按年级、目标国家、专业方向匹配模板
  • 提示词：输出必须覆盖语言、背景提升、申请节奏三大阶段
  • 约束：每个里程碑必须带可检查的交付物和截止日
  • 知识 / 回退：基于历年成功案例模板；特殊背景（如转专业、gap）转资深顾问
04
评测证据

基于历年成功 case 抽象规划模板；输出与资深顾问手工规划对比，结构一致率 92%；失败案例 = 转专业学生缺少补修节点，已新增「转专业补修」分支模板。

05
迭代与风险

下一步：从规则引擎升级为学生可对话追问的 Agent，支持动态调整。误判控制：截止日期二次确认；学生目标等敏感信息本地存储。

营养学信息源导航

信源分级知识导航RAG 喂料跨域迁移
01
用户问题

营养学学生面对海量健康信息，难辨官方、行业、商业信源，容易引用二手甚至错误信息。

02
可运行工作流

输入：收集到的 Nutrition/健康信息源 → AI 处理：按「官方 / 行业 / 商业」三级自动分级 → 人工复核：边界案例逐条确认 → 输出：结构化导航页，每条附原始 URL 与引用建议。

03
AI 策略
  • 分类：按发布主体 + 同行评审 + 更新频率定义三级信源
  • 提示词：输出必须包含「机构类型 + 证据等级 + 原始 URL」
  • 约束：商业来源即使引用官方研究，也不得上浮为官方级
  • 回退：模糊来源标记「待复核」，不自动分级
04
评测证据

覆盖数十条跨国 Nutrition 信息源；人工复核边界案例后，分级准确率 95%；失败案例 = 某商业博客引用官方研究被误判为官方源，后增加「内容主体」维度修正。

05
迭代与风险

下一步：增加时效性标签与失效链接检测。误判控制：所有引用必须回到一手来源核实；无原始 URL 的信息源不纳入导航。

09 / Competitive Research

竞品与市场验证：申学邦Proving the Problem is Real.

我的方案不是闭门造车。完成工作台后，我对市面上主流的留学智能管理 SaaS「申学邦」做了市场调研，验证痛点与机会。

BACKGROUND

申学邦是一份面向留学机构的智能管理 SaaS 解决方案。其方案指出：留学行业近 90% 的机构未采用数字化系统，原因包括无对口产品、成本开销大、研发难度高。申学邦提供查校版（6,000 元/年）、CRM 版（6,000 元/年）、服务管理版（8,000 元/年）、全流程版（16,000 元/年）等套餐，覆盖招生、规划、院校、文书、申请、签证等模块。

维度申学邦我的方案

验证结论

问题真实存在：申学邦的行业分析证实，留学服务数字化程度低、信息碎片化是普遍痛点。
我的方案有差异化：不追求大而全的机构级 SaaS，而是聚焦顾问每日最高频的「选校 + 时间表 + 签证/行前」三个动作，用自然语言把工作流压缩到分钟级。
同事验证有效：已把选校/时间表功能分享给同事，原本 30–60 分钟的整理工作，现在约 3 分钟完成，且输出格式统一、可复核。
